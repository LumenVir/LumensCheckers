# 跳棋 v1.2 金币系统 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不改变跳棋胜负规则的前提下，加入长期金币、本局账本、本回合奖励、悔棋扣费、目标格奖励和落地冒币动画。

**Architecture:** 金币统一用整数存储，1 单位等于 0.1 金币。纯奖励计算放在 `rules.js` 并使用 Node 测试；浏览器层负责昵称档案、本局与本回合账本、结束回合结算及动画。长期余额只保存到 `localStorage`，不保存进行中的棋局。

**Tech Stack:** 原生 HTML、CSS、JavaScript，Node `assert` 测试，浏览器 `localStorage`。

### Task 1: 金币纯规则

**Files:**
- Modify: `checkers-web/rules.js`
- Modify: `checkers-web/rules.test.js`

**Steps:**

1. 先为连续跳、隔空跳、奖励上限和目标格四层价值编写失败测试。
2. 实现 `calculateJumpReward`、`createTargetRewardMap`、`formatCoinUnits`。
3. 运行 `node checkers-web/rules.test.js`，预期全部通过。

### Task 2: 玩家档案与金币账本

**Files:**
- Modify: `checkers-web/app.js`
- Modify: `checkers-web/index.html`

**Steps:**

1. 使用昵称解析或创建本地玩家档案，新玩家初始 100 单位金币。
2. 禁止同一局使用重复昵称，避免三个玩家引用同一钱包。
3. 增加总金币、本局金币和本回合待结算显示。
4. 标准开局启用金币；随机和胜利测试场景禁用金币。

### Task 3: 行动奖励与悔棋扣费

**Files:**
- Modify: `checkers-web/app.js`
- Modify: `checkers-web/style.css`

**Steps:**

1. 每次跳跃完成后增加本回合临时奖励，并在棋子上方显示金币图标和数值。
2. 历史快照同时保存连跳次数和临时奖励，使悔棋能撤销相应奖励。
3. 每回合第一次悔棋记录 5 单位费用，后续悔棋不重复收费且费用不随回退撤销。
4. 点击结束回合时，将跳跃奖励、目标格奖励和悔棋费合并进入本局账本。

### Task 4: 目标格与整局结算

**Files:**
- Modify: `checkers-web/app.js`
- Modify: `checkers-web/rules.test.js`

**Steps:**

1. 仅在结束回合时检查最终落点，领取尚未领取的目标格奖励。
2. 每局记录已领取目标格；重新开始时清空并作废本局收益。
3. 三方名次全部确定后，把各玩家本局收益计入长期余额，余额最低为 0。
4. 保存长期玩家档案到浏览器，不保存棋盘残局。
